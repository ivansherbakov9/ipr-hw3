**Отчёт по ДЗ Docker**

**1. Запуск приложения**

Написал Dockerfile и собрал образ приложения. Запустил контейнер, передал приветствие через переменную окружения. Проверил счетчик через curl, POST-запросы увеличивают его на 1. Логи сохранил в logs.txt.

**2. Docker Compose**

Настроил запуск через compose. Порт и приветствие вынес в .env. Подключил volume для sqlite и проверил сохранение счетчика: после удаления контейнера значение осталось 3.

**3. Redis**

Добавил отдельный сервис redis. Приложние подключается к нему по имени сервиса redis. Для redis включил сохранение данных на диск и подключил volume. Для обоих сервисов добавил healthcheck.

**4. Проверка сохранения данных**

Увеличил счетчик до 4. Выполнил `docker compose down`, затем `docker compose up -d`. После повторного запуска счетчик остался 4.

**5. Проверка при отключении Redis**

Остановил redis через `docker compose stop redis`. Проверил запросы:

- GET /healthz - 200
- GET /readyz - 503
- POST /increment - 503

**6. Восстановление Redis**

Запустил redis обратно. Без перезапуска приложения счетчик остался 4, следующий POST увеличил его до 5.

**Итог**

Приложение работает через Docker Compose, данные сохраняются после пересоздания контейнеров, а при отключении redis сервер возвращает нужные HTTP-коды.
